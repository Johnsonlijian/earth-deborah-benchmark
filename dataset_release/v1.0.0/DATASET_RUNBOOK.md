# Reproducible runbook — Dataset version 1.0.0

## Reuse the deposited tables

1. Verify `metadata/RELEASE_CHECKSUMS_SHA256.csv` against the extracted files.
2. Tables are stored in `data/derived_tables/`. Their original generation
   paths and source-to-archive mapping are in `metadata/SOURCE_MANIFEST_R68.csv`.
3. The field dictionary and interpretation limits are described in the
   associated data descriptor. No raw archive download is needed to inspect
   the deposited tables and figures.

## Rerun analysis in a separate working directory

The archive preserves the code and inputs-to-outputs mapping; it does not
include raw provider time series. A full numerical rerun was not performed
for this documentation refresh.

- Copy `code/` contents into a new working directory. Install dependencies
  from `code/environment.yml` or `code/pyproject.toml` as appropriate; optional
  hydrological-model dependencies and permitted raw inputs are required for
  the complete pipeline.
- Historical scripts locate their working root from their own location and
  expect `reports/tables/`, `reports/figures/` and `data/external/` beneath it.
  Map `data/derived_tables/` to `reports/tables/` for reuse of existing outputs.
- Figure 5's renderer is archived at
  `code/paper_figures/render_essd_fig05_decision_test.py`. In a reconstructed
  project it belongs under `paper_figures/src/`, as recorded by the source
  manifest. Preserve that depth so its relative-root calculation is correct.
- Use `metadata/SOURCE_MANIFEST_R68.csv` to reconstruct other required original
  paths. The preregistration is stored at
  `docs/preregistration/preregistration_v1.md`; restore the original path
  recorded in the source manifest before running the decision-test script.
- Obtain any required raw data from `DATASETS_AND_LINKS.csv`, retaining the
  provider version, licence and attribution. No raw files are supplied here.

## Analysis order

Archive-specific spectral processing precedes null-reference generation and
uncertainty calculations. The CAMELS-GB model layer is generated by
`scripts/run_r39_open_model_intercomparison.py`; the preregistered comparison
uses `scripts/run_r62_decision_poc_gb.py`. The ESSD figures are generated by
`scripts/run_r65_essd_figures.py` and the Figure 5 renderer identified above.
Consult each preserved script for its command-line arguments and dependency
paths rather than assuming the deposit layout is its execution layout.

## Interpretation and provenance

The product supports bounded characterization and model comparison. It does
not establish a physical storage mechanism or a universal ranking rule.
The archived code snapshot is separately identified from the historical
GitHub snapshot in the root README. Numerical content has not been
changed by this documentation refresh.
